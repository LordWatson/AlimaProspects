# CLAUDE.md — AlimaProspects

Root instructions for Claude Code (and humans). Read this first, every session.

AlimaProspects is a multi-tenant SaaS that helps businesses find, qualify and contact prospects with AI (web + mobile). See `docs/architecture.md` for the system map and `mvp.md` for the phased build plan.

---

## 0. Golden rules

- **Never commit secrets.** Never weaken tenancy scoping, transactions, or tests to make something pass.
- If a requirement is unclear or conflicts with these rules, **stop and ask**.
- A phase is **not complete** until: `composer test` green, `composer analyse` clean (Larastan ≥ level 6; repo is at **7**), frontend `npm run check` + `npm run types:check` + `npm run build` pass, and **docs are updated**.
- **The brand is law (see §2a).** Any UI — web or mobile — must obey the Alima brand defined in the two source PDFs. Do not invent colours, type, spacing, logo treatment or tone.

## 2a. Brand — the source of truth (read before ANY frontend work)

The authoritative brand lives in **two PDFs**, both in **`.claude/docs/brand/`** (originals) and mirrored in **`docs/brand/`**:

- **`Alima — Brand Guidelines.pdf`** — the full 67-page system: logo, colour, typography, elements, voice, digital tokens, print.
- **`Alima.pdf`** — the companion brand file.

Before building or changing any screen, component, email, or mobile view:

1. **Read `docs/brand/brand-tokens.md`** — the engineering extraction of the PDFs (palette with hex, semantic digital tokens, type scale, radius/shadow/motion, spacing/grid, logo rules, voice). If a detail you need isn't there, **open the PDFs** and, if useful, extract more into `brand-tokens.md`.
2. **Build with tokens, never raw hex.** Colours/type/spacing come from the Tailwind `@theme` tokens (encoded in Phase 2 from `brand-tokens.md`), not hand-picked values.
3. **Obey the non-negotiables:** lead with Cloud Cream, one hero accent per layout; **Signal Orange is decorative only — never a status colour** (use `status.*`); Poppins (Latin) / Tajawal (Arabic) / DM Mono (labels); logo clear-space, min-sizes and approved colourways; WCAG AA; **EN/AR + RTL**; brand voice (bright, bold, clear, together) for all copy.
4. **When in doubt:** fewer colours, more cream, a bigger logo — then ask. Anything not covered by the PDFs is flagged for brand-owner approval (see `brand-tokens.md §7`), never silently invented.

Changes to brand interpretation are recorded in `brand-tokens.md`; the PDFs themselves are the fixed reference.

## 1. Environment & commands (Windows + Laravel Herd)

- Local dev is **Laravel Herd**. The machine also has Laragon and **Laragon wins the PATH**, so a bare `php`/`composer` may be the wrong (8.3) version. **Always use Herd's binaries:**
    - PHP 8.5: `C:/Users/alexa/.config/herd/bin/php.bat`
    - Composer: `C:/Users/alexa/.config/herd/bin/composer.bat`
- **Horizon can't run on Windows** (needs `ext-pcntl`/`ext-posix`). It is installed for Linux prod/CI via `config.platform` in `composer.json`. Locally use `php artisan queue:work`; don't run `php artisan horizon` on Windows.

| ------------------- | -------------------------------------------------------------- |

## 2. Architecture rules (non-negotiable)

### Structure — domain modules (ADR 0002)

Code lives under `app/Modules/<Module>/` with: `Actions/ Services/ Contracts/ Data/ Enums/ Events/ Listeners/ Jobs/ Models/ Policies/ Support/ Observability/ Http/{Controllers/Web, Controllers/Api/V1, Requests, Resources}/ Exceptions/ routes/{web,api}.php Providers/<Module>ServiceProvider.php`. (`Support/` is small collaborators that are neither an Action nor a Service; **`Observability/`** is code whose job is to report what the module is doing and which could be deleted with the product still working — a Pulse recorder is not a `Listeners/` listener for that reason. Both are explained in ADR 0002.) Migrations/factories/seeders stay in standard Laravel dirs but are **named by module**. Tests in `tests/Feature/<Module>` + `tests/Unit/<Module>`. Frontend in `resources/js/Pages/<Module>/` + `resources/js/Components/<Module>/`. Each module has a `<Module>ServiceProvider` registered via the Core base provider.

### Code rules

- **Thin controllers:** authorise (Policy) → validate (FormRequest) → call **one** Action/Service → return (Inertia page or API Resource). No queries, no business logic, no try/catch soup in controllers.
- **Actions** = single operations (`CreateLeadAction`). **Services** = orchestration / third-party integrations. Pass DTOs in, return models/DTOs out.
- **All writes in `DB::transaction()`** at the Action level. Post-commit work (jobs, events, emails, external calls) uses `DB::afterCommit()` / `afterCommit`. **Never call external APIs inside a transaction.**
- **Multi-tenancy (ADR 0006):** every tenant table has `team_id`. Use the `BelongsToTeam` trait (global scope + auto-assign). **Policies double-check ownership.** Every tenant model needs a test proving cross-tenant access fails.
- **Logging:** structured + contextual (`Log::withContext(['team_id','user_id','request_id'])`); a channel per module where one earns it — `ai`, `lead_sourcing`, `signals`, `outreach`, `notifications`, `insights`, `billing` (add yours to `config/logging.php` and say so in the module doc). **Never log secrets or full personal data — log IDs.**
- **Errors:** domain-specific exceptions per module (extend `App\Modules\Core\Exceptions\DomainException`), rendered centrally in `bootstrap/app.php`. Friendly to users; details to logs/Sentry. External calls use timeouts, retries w/ backoff, circuit-breaker guards.
- **Jobs:** idempotent; `ShouldBeUnique` where duplicates harm; set `$tries`, `$backoff`, `$timeout`; implement `failed()`. Long AI/lead jobs report progress over Reverb.
- **Validation** only in FormRequests/Data. **Authorisation** only in Policies/Gates. **Compliance
  gating is neither** — whether a lead may be approached is `Outreach\Services\OutreachGuard`'s
  answer, not a policy's: authorisation asks whether this member may act, the guard asks whether this
  prospect may be approached, and conflating them means a legal rule enforced by a role check.
- **Never notify directly.** Raising a notification is
  `Notifications\Services\NotificationDispatcher` (`send` / `toTeam` / `toAdmins`) — never Laravel's
  facade, never `$user->notify()`. The dispatcher is what resolves the member's per-team channel
  preferences, stamps `team_id` on the row, drops members who have left, and keeps the stored payload
  free of prose (keys + params, never a sentence). A notification that would fan out per record needs
  **aggregating** first — see `AnnounceTopLeadsJob` for the pattern.
- **Anything that reaches a prospect goes through Outreach.** Suppression, sender identification and
  the opt-out are conditions of sending, not features of a screen (`docs/compliance.md` §3.2–3.3).
- **Enums** for every status/type column. **No magic strings.**
- **Money** = integer minor units. **Timestamps** UTC in DB, displayed in team timezone.
- **Strict types** (`declare(strict_types=1);`) in every PHP file; typed properties + return types everywhere.
- **Eloquent:** `Model::shouldBeStrict()` outside production; avoid N+1 (eager load; test with `preventLazyLoading`).
- **API:** versioned `/api/v1`, **API Resources only** (never return models), consistent error envelope, pagination, per-token rate limiting. Since **Phase 17** each of those is a property of _every_ endpoint, asserted over the whole route table in `tests/Feature/Api/V1/RouteContractTest.php` — a new route must be declared by its own module (`routes/api.php` is deliberately empty), named, behind `auth:sanctum`, scoped with an `ability:` from `Auth\Enums\TokenAbility`, and present in `docs/api/openapi.json`. The error envelope has one definition, `Core\Http\Responses\ApiError`; a module adds a failure mode by extending `DomainException` with its own code, never by inventing a response shape. Scoped **by path** (`api/*`), because the web forms depend on Laravel's native 422 for their error bags. `per_page` comes from `Core\Http\Requests\PaginatedIndexRequest`.
- **Frontend:** **obey the brand (§2a)** — the two PDFs in `.claude/docs/brand/` + `docs/brand/`, via `docs/brand/brand-tokens.md`. Brand tokens as Tailwind theme vars, never raw hex; build reusable base components (`Button`, `Input`, `Card`, `Table`, `Modal`, `Badge`, `EmptyState`, `Toast`) before feature screens; responsive + accessible (WCAG AA, keyboard nav, labels); **EN/AR + RTL** (ADR 0007). Signal Orange is decorative only, never a status colour.
- **Tests:** every Action has a unit/feature test; every endpoint has a feature test covering auth, validation, tenancy and happy path. **Fake external providers** (AI, lead sources, Stripe) in tests.

## 3. Where things live

- `app/Modules/<Module>/` — domain code. `app/Modules/Core/` — tenancy, audit, base classes, logging, exceptions, **the response security headers and the Sentry scrubber** (Phase 20).
- **Phase 20 (Observability & security hardening) is complete** — read **ADR 0017** before touching
  anything in `config/security.php`, `config/observability.php`, `config/sentry.php`,
  `config/pulse.php` or `app/Modules/Core/{Observability,Support/Security}`, and
  **`docs/runbooks/observability.md`** when something is broken in production. Five things about it
  are easy to get wrong. `SecurityHeaders` is **global** middleware, not a group — the headers
  belong to the response, and a group is how the one route nobody thought about becomes the one
  route without a header. The **CSP is nonce-based with no `unsafe-inline`**, which is only
  affordable because this app has no third-party script: a new inline tag needs the nonce
  (`Vite::cspNonce()`), and a new third-party host goes in `SECURITY_CSP_EXTRA_*` rather than into a
  loosened directive — and it is deliberately **not** emitted under `npm run dev`, so test a policy
  change against a built environment. Sentry's **scrubber is aimed at our own code**: the realistic
  leak is a log context becoming a breadcrumb, so log IDs, never prose or payloads, and add a key to
  `observability.sentry.scrub` rather than trusting the vendor's defaults. **A new expected refusal
  belongs in `sentry.ignore_exceptions`** with a comment, because that list is also the list of
  things we have decided not to be told about — but never the base `DomainException`. And `/pulse`
  is behind the admin panel's own four controls plus `AdminAbility::ManageOperations`: it is a
  cross-tenant surface, not a lesser one, and **Pulse is a clock while `/admin` is a tenant** —
  neither answers the other's question.
- `docs/` — knowledge base: `architecture.md`, `modules/<module>.md` (read before working a module), `decisions/` (ADRs), `runbooks/`, `compliance.md`, `ai-prompts.md`, `brand/brand-tokens.md`.
- `mvp.md` — phased plan + status table. **Phases 11 (Outreach), 12 (Notifications), 13 (Reporting & Analytics), 14 (AI Insights), 15 (Compliance & Privacy), 16 (Billing & Plans) and 17 (API v1 hardening) are complete** — read `docs/modules/outreach.md`, `docs/modules/notifications.md`, `docs/modules/reporting-analytics.md`, `docs/modules/ai-insights.md`, `docs/modules/compliance-privacy.md` and `docs/modules/billing-plans.md` before touching any of them. Compliance in particular: it reaches other modules through **three contracts, not by them knowing about it** — `LeadSourcing\Contracts\LeadInterestGate` (no recorded lawful basis, no discovery), `Outreach\Contracts\LeadRestrictionResolver` (how a prospect may be approached) and `Signals\Services\SignalsPersonalDataExporter`. Add a compliance rule by binding one of those, not by importing `App\Modules\Compliance` into another module. The do-not-contact table stays `outreach_suppressions`. Billing works the same way and is the **last** provider registered: it binds the real `AiPlatform\Contracts\CreditSource`, `LeadSourcing\Contracts\LeadQuotaSource` and `Auth\Contracts\SeatLimitSource` over the permissive stubs those modules ship as defaults, so no module imports `App\Modules\Billing` — change a plan limit by changing `config/billing.php` or one of those bindings, never by teaching another module what a plan is. Enforcement lives in the **guards**, not in middleware, because a queued discovery job and a scheduled watch spend a team's allowance with no request behind them; it can be switched off wholesale with **`BILLING_ENFORCE_PLANS=false`**, which makes the provider install neither the plan capability gate nor the three sources so each module's own permissive default stands (suspension, operator overrides and the AI cost allowance all keep biting), and **`BILLING_STRIPE_ENABLED=false`** separately stops every Stripe call without touching anybody's entitlement — the two are different questions and neither implies the other; and `usage_meters` is a **record** over the `ai_requests`/`discovery_runs` ledgers, not a counter the app increments. Reporting in particular: every figure is scoped by one window whose **cohort rule** is written down there, and its bounds must reach a query in **UTC** (`DateRange::constrain()`) or a non-UTC team's dashboard silently shifts. `signals-plan.md` — the Signals (trigger-event prospecting) build plan, phases S0–S6, **complete** (companion to `mvp.md`; see `docs/modules/signals.md`, `docs/runbooks/signals-demo.md` + ADR 0011). `signals-v2-plan.md` — the Signals v2 plan, phases **S7–S16**; **S7, S8, S9, S10, S11, S12 and S13 (a and b) are complete** (signal types are data a team owns — ADR 0018; the geography is plural and the outreach restriction follows the signal's own jurisdiction — ADR 0019; the builder drafts a type from a sentence and previews it before saving — ADR 0020; a watch can be pointed at the team's own accounts instead of a place — ADR 0021; one event is one card, and an article's identity survives a redirector; the feed is ranked, every card explains itself and the team's dismissals propose the next tuning — ADR 0022; a signal source is a registry entry and a type says which sources it runs on — ADR 0023, and S13b finished the set: the public record, a feed a team chooses, and a customer's own events), S14–S16 are planned. **After S9 the original ask is delivered**; everything after it is the moat. Fifteen things about Signals that are easy to get wrong after S13: a signal **type** is a row and not an enum (`SignalDefinition`; the four status/cadence/reason enums stay enums, and ADR 0018 §1 is the test for which is which), and `signal_definitions` is the one table holding both tenant rows and **platform presets** — only `PlatformPresetReader` may read a preset, a team **clones** one rather than referencing it, and nobody edits one. The query builder no longer reads `config('signals.templates')`: that key is seed data for the presets. Third, **where a watch searches and which law applies to its leads are two different questions** — `SearchRegion` answers the first, `Market` the second, and ADR 0019 is why `Market` must not grow to cover a region nobody has taken a legal position on. Fourth, the restriction on a converted lead **follows the subject**: the signal's own `resolved_market` first, the watch's `market` as a backstop, its regions able only to add, and an unresolvable place failing _toward_ the restriction — keying it on the watch alone was a permissive compliance bug (`docs/compliance.md` §3.11). Fifth, the composer **never saves** and the preview **persists nothing** — a draft is a suggestion the member commits, and a preview writes only its `signal_previews` ledger row, which is what makes the team's daily preview budget enforceable. Sixth, **a preset's templates are never shipped unspiked**: every one in the library has been run against live Serper `/news` and recorded in the module doc's spike tables, because a preset nobody ran is a guess with a label on it — eight of S9's 66 returned zero, and S10's spike contradicted its own plan (**every quoted query returned zero, 12/12**, and adding a keyword to a company name _lost_ results), which is why an entity query is a **bare name**. Seventh, a watch is **either** topical **or** entity-scoped — `signal_watches.signal_watchlist_id` decides, a spec carries places or entities and never both, and a long watchlist is a **ring** read through `entity_cursor` — a window filled by what one run can **afford** (one query per entity per region), advanced by the entities actually searched, rather than a list trimmed to its first forty forever. Eighth, `signals.matched_lead_id` ("the lead this is **about**") is not `signals.lead_id` ("the lead this was **converted into**"); the match is written as the row is built, with the lead's timeline entry **inside the same transaction**, and "Add to {Lead}" is `ConvertSignalToLeadAction` with a named target rather than a second Action. There are exactly **two** match confidences and a weak guess is **no match** — and the one company-name rule lives in `LeadSourcing\Support\CompanyNameKey` (`for()` strict, `bare()` **legal forms only**: do not put `holdings` or `group` back in that list, which is how "Acme" came to match "Acme Holdings Ltd"). Ninth, `SignalScope` is a **scope, not a status** — it crosses the status tabs rather than extending them, and the tab counts are scoped with it. Tenth, **a signal is one article and a `SignalCluster` is one event**, and the feed lists and counts the cluster's `primary_signal_id`: a member never actions a member row, so dismiss, restore and convert are propagated across the cluster while `lead_id` deliberately is not (exactly one article is a lead's provenance). `SignalClusterer` holds **two** questions — a provisional headline overlap _before_ the AI (which is where the one-classification-per-story saving comes from, and which `signals.cluster_before_ai=false` turns off safely) and the real `(event_key, subject fingerprint, ISO week)` key _after_ it (which is what consolidates the cards either way). So the savings depend on the similarity numbers and the correctness does not; the fingerprint is a **company** name and never a person's, because a cluster has no retention window of its own. Eleventh, **`signals.dedupe_hash` is an article's identity and `url_hash` is only its link**: for a host on `signals.redirect_hosts` the identity is the content hash (`sha1(source name + normalised headline)`), because a Google redirect's token cannot be unwrapped and a varying one re-admitted the same article on every run. The unique index moved with it, the ignore list matches an **outlet's name** as well as a host for the same reason, and `SignalRejectionLedger` remembers a "no" for 30 days keyed by the article _and_ the set of types that were offered — never for a key the run did not offer, because that is a statement about our prompt rather than about the article. Twelfth, **`signals.heat` is nullable and an unjudged component is left out of _both_ sides of the average** — `null` is “not scored”, not “scored zero”, or the number would measure how much Alima knows about an event instead of how much the event is worth, and `SignalSortOrder` orders nulls last explicitly because MySQL and SQLite disagree. `signals.score_breakdown` is **stored and read back, never recomputed**, because the card must explain the score the feed was actually ordered by; its figures are literal and only Alima's own sentences carry `evidence_translatable`. `SignalTuningAdvisor` **proposes and never applies** — accepting is an ordinary audited edit, a decline is kept so it is never raised twice, and “raise this floor” may never lower one. The full-article fetch is **off by default**, reuses `Core\Contracts\WebContentFetcher` and the existing `signals.extract_event` prompt, honours `robots.txt` via `Core\Support\RobotsPolicy`, and **stores no body** — only `article_fetched_at`; it runs **after** the run's commit, so nothing in it may escape (ADR 0022). Thirteenth, **a signal source is an enum and a signal type is a row, and that is not a contradiction** — ADR 0018 §1's test still decides it: a class exists per source, so the application branches on one and not on the other. `SignalSourceKind::isAvailable()` separates a case that is wired up from one only declared (`companies_house`, `feed` and `webhook` are declared), and a definition cannot be saved against an unavailable one. Add a source by registering a `SignalSourceProvider` in `SignalsServiceProvider`, never by branching in the run; give it its **own** breaker key under `signals:cb` and a matching `Admin\Enums\PlatformProvider` case, or an open breaker is invisible to operations. `signal_definitions.source_keys` is **read through `sourceKinds()`**, which falls back to news for a null, an empty list or a key this build does not know — a type that searched nowhere would complete a run successfully having found nothing. And the one to hold on to: **a provider's health and a query's validity are different questions.** A 400 or 422 **whose body matches `signals.serper.query_rejection_markers`** is a verdict about _that query_ (Serper refuses `site:` and quoted templates on this account tier), so it raises the non-retryable `SourceQueryRejected`, leaves the breaker shut, is caught **per query** by a typed `catch` and is counted under `rejected` on `signal_runs.source_breakdown` while the rest of the plan proceeds — treating it as an outage made one team's bad template fail and re-bill their whole run three times over. **Any other 400 fails the run loudly**, because the same status is how an exhausted account and a parameter we send wrongly arrive, and swallowing those per query would complete every run green with nothing found, for ever; and a source that refused **every** query fails the run too, because “some refused” is about a template and “all refused” is about something systemic (ADR 0023 §4). Fourteenth, **a source is addressed in one of three ways, and mixing them up is a cost bug in the expensive direction** (S13b): a _query-based_ source (`isQueryBased()` — news, web search) takes a string and multiplies out by place × region × template; a _subject-addressed_ one (`addressesSubject()` — Companies House) takes a company number, so one query per account and no multiplication, which is also why it runs on a **watchlist watch only** — there is no cross-company filings endpoint, and the topical half of its task was dropped on evidence (2,422 new London software companies a month for one SIC code); and a _definition-addressed_ one (a feed, the webhook) takes what is on the definition, so one query each — a feed asked per place per region per template would be fetched forty times a run for one identical document. Three more S13b rules worth holding. A **registry filing carries its own classification and skips the AI batch** (`SourceItem::$classification`, `ExtractedSignal::structured()`), because `description_values` is the registry’s own extraction — but it still passes `resolveDefinition()` and the definition’s floors, since a source asserts a confidence and not that the team wants the event; only code **we** wrote against an authoritative provider may populate that field, never the webhook. A **watchlist name is resolved to a company number once and remembered**, from `leads.company_number` for free where the team’s own data knows and otherwise from a search that accepts **only an exact `CompanyNameKey::for()` match** (never `bare()`) — a filing arrives with confidence 100, so nothing downstream would doubt a wrong company; `company_number_checked_at` is the negative cache, and a _transport_ failure must leave it unstamped. And a **pushed event is stored, then read back like any other source**: `POST /api/v1/signal-events` accepts into `signal_inbound_events` and `WebhookSignalSource` offers it to the next run, which is what makes “the customer supplies an observation, Alima decides what it means” true rather than aspirational — and what keeps a retry loop from triggering an AI call. Its secret is **encrypted, not hashed** (verifying an HMAC means recomputing it), shown once, one per type; its window must stay **below** the 30-day rejection memory, because there is deliberately no `processed_at`. The SSRF guard for the one source whose address a customer supplies is `Core\Support\Security\SafeUrl`, **shared** with `HttpWebContentFetcher` and never copied; it now hands back the addresses it approved so the feed can **pin** them, and a feed whose host does not resolve is refused rather than attempted. And the S13b review added the **fifteenth**, which is ADR 0023 §4a: **a 4xx has three meanings, not two** — a breaker answers _is the provider up_, `SourceQueryRejected` answers _was that a sensible thing to ask_, and `SourceAddressNotFound` answers _is the thing we addressed there at all_. The third exists because the first two are both questions about **us**, which was exhaustive only while every source was addressed by a string we composed: as a provider failure one struck-off `leads.company_number` failed a whole watch on every run for ever (the entity cursor only advances on completion), and as a query rejection a moved feed failed a run too, because a feed is asked **one** query so "some refused" and "all refused" are the same event. A skip is caught per query, counted under `skipped` on the breakdown, and excluded from the all-refused rule. Three more things that review settled and that generalise past Signals: a **cache key is a tenancy decision** (the feed's poll floor and ETag were keyed by URL alone, so one team's poll of a public newsletter silently blinded every other team — a denial, not a leak, which is the half nobody tests for, and a preview must hold none of a run's state); a **capped window must exclude what it has already done** before the cap is spent (`signal_inbound_events.dedupe_hash` exists so the exclusion can be a `whereNotExists` rather than a filter after the fact, because `sha1()` is not a function SQLite and MySQL agree about); and **`! isQueryBased()` is not "addresses a subject"** — that conflation put a feed query behind every template and a phantom registry query behind every entity, so ask the enum the question you mean (`addressesSubject()`, `carriesAFetchableArticle()`). `CHANGELOG.md` — notable changes.

- Config: `.env.example` documents every key. **Brand PDFs in `.claude/docs/brand/` and `docs/brand/`** (`Alima — Brand Guidelines.pdf`, `Alima.pdf`) → extracted to `docs/brand/brand-tokens.md`. See §2a.

## 4. How to work a phase (ADR + §8 of the kickoff)

1. Read this file, the phase in `mvp.md`, and the relevant `docs/modules/*.md`.
2. Plan briefly, then implement in **small commits** with **conventional commit messages**.
3. Write/update tests alongside the code.
4. Run `composer lint`, `composer analyse`, `composer test`, and the frontend build; fix everything.
5. Update the module doc(s) (Code map, Data model, Key flows, **Changelog row**), `docs/architecture.md` if structure changed, `CHANGELOG.md`, and tick tasks + the status table in `mvp.md`.
6. Summarise what was done, anything deferred, and anything the user must do (keys, accounts, decisions).

**Before working on a module:** read its `docs/modules/<module>.md`. **After finishing:** update that doc and append a Changelog row. New module → create its doc from `docs/modules/_TEMPLATE.md` and add it to `architecture.md` + this file.

`security:posture` checks the **machine**, not the repository) · 0018 **signal types are data, not an enum** (Signals S7: a `SignalDefinition` is a row a team owns, so a new kind of trigger event is configuration rather than a deploy; the exception to §2's "enums for every type column" is decided by one test — _does the application branch on the value?_ — which the status, run-status, cadence and dismiss-reason enums pass and the event type never did; `team_id = null` is a **platform preset** and `Signals\Services\PlatformPresetReader` is the one place that removes the tenancy scope to read one; a team **clones** a preset rather than referencing it, so a platform edit never silently changes what they are paying to run; and the AI schema's `event_type` enum could not survive per-team keys, so `RunSignalWatchAction` became the guard the schema used to be) · 0019 **search geography is not the compliance market** (Signals S8: `SearchRegion` answers _where do we look_ and `Market` answers _which rules apply_, and one column was doing both; `Market` deliberately does **not** grow to the new regions, because every case on it asserts a legal position the business has taken, so `SearchRegion::market()` is nullable, a region with no position contributes nothing to a lead's restriction and is **not offered** at all; the outreach restriction follows the **subject** — the signal's own resolved jurisdiction first, the watch's `market` as a backstop, its regions able only to _add_ — and an unresolvable place fails **toward** the restriction, never away from it; "most restrictive" is asked of `OutreachRestriction::allowsDirectMarketing()` rather than hard-coded; see `docs/compliance.md` §3.11 for the general rule every later source is held to) · 0020 **the signal builder** (Signals S9: an AI that writes **configuration** rather than prose gets different rules — it **drafts and never saves**, its output is bounded three times (the schema, the _save path's own_ validation rules, and `UntrustedContent` round the brief), and it is **previewed against reality before it is kept**, because the S0 spike established that nobody can tell whether a query template works by reading it; a refusal is a first-class answer; the preview persists **no signals** and one `signal_previews` row, because a user-triggered spend loop needs a cap and a cost with no ledger row cannot be capped; three independent caps, one of them team-wide and therefore in the Action; `Capability::SignalComposer` gates the AI shortcut **only**, since gating the builder would make the cheaper plans worse than before it existed; a preset's **pack** lives in the catalogue and not on the row) · 0021 **account monitoring** (Signals S10: a watch carries **either** places or a watchlist, never both, because conflating them multiplies one cost by the other; a per-run ceiling over a long list has to **rotate** (`entity_cursor`) rather than trim, or the eighty-ninth account is never searched at all, silently, forever; `matched_lead_id` — the lead an event is _about_ — is written as the row is built, with the lead's timeline entry in the **same transaction**, so a history never claims an event the feed cannot show; exactly **two** match confidences and no third, because a weak guess is not a match and the way this fails is an event pinned to the wrong company — the confidence is shown in words and _Convert anyway_ is a real button; one name rule in `LeadSourcing\Support\CompanyNameKey`, stripping **legal forms only**; the account notification is addressed to the **lead's owners** and aggregated per run, because an event about an account somebody works is not the team's to ignore; and the spike the plan asked for contradicted the plan — quoted queries return nothing and a keyword costs results, so an entity query is a bare name) · 0022 **a ranked feed that can explain itself** (Signals S12: the scorer is deterministic and its components are **stored** rather than recomputed, because an explanation is of the decision that was taken and not of the one today’s weights would take; **unknown is not zero** on either side of the average, and `signals.heat` is nullable for the same reason one level up; a system that learns **proposes** — accepting a suggestion is an ordinary audited edit, a decline is kept so it is never raised twice, and “raise this floor” may never lower one; the full-article fetch is a five-way-bounded exception that reuses Core’s fetcher and the existing prompt and **stores no prose**, running after the commit where nothing may escape; and signal performance is reported over cluster representatives, with “worked” meaning off the default stage because a named stage is not comparable between teams) · 0023 **signal sources are a registry, and an inbound event is untrusted** (Signals S13a: a source sits behind `SignalSourceProvider` + `SignalSourceRegistry`, the deliberate mirror of ADR 0008's pair, with the breaker keyed **per source** so one endpoint's outage is not another's; a source **key** is an enum while a signal **type** is a row, because a class exists per source and ADR 0018 §1's test cuts that way; a 4xx has two meanings and conflating them is expensive — a breaker answers _is the provider up_ and `SourceQueryRejected` answers _was that a sensible thing to ask_, so a refused query pattern is skipped and counted rather than failing and re-billing a whole run — but the **body**, not the status, is what says so (`signals.serper.query_rejection_markers`), because a 400 is also how an exhausted account arrives, and a source that refused **every** query fails the run rather than completing green; a structured source may carry its own confidence and skip the AI batch, which only code **we** wrote against an authoritative provider may do; and an inbound webhook is signed, replay-protected, bounded, rate-limited, wrapped in `UntrustedContent`, and never believed about a score, a jurisdiction or a lead id — the jurisdiction one is not a judgement call, it decides whether cold outreach is lawful; S13b implemented all of it, and added the third **addressing** shape the registry and the feed forced — query-based, subject-addressed, definition-addressed)

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:

- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.
